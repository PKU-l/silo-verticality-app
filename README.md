# 筒仓滑模垂直度观测与偏移可视化（九仓版）

用于 3×3 共九座筒仓（10～18 号）的观测数据管理，主要场景有三个：手机录入、九仓总览、单仓偏移分析。
**图形严格反映量测数据**：缺少的方向不补零，只有单侧读数时不生成中心点；无数据的仓显示“未观测”，不画成零偏移。

## 运行

需要 Node.js 18 及以上版本。

```bash
npm install
npm run dev          # 开发模式
npm test             # 单元测试（计算、方向、布局、同步冲突）
npm run build        # 生成 dist/，可部署到任意静态网站服务器（需 HTTPS 才能安装为 PWA）
npm run sync-server  # 可选：参考同步服务器，同时托管 dist/，默认 http://localhost:8787
npm run e2e          # 可选：垂准仪模式离线/同步端到端测试（需先 build 并启动 sync-server，本机需装 Edge）
node e2e/dist-offline.mjs  # 可选：八点模式端到端测试（填写基准、断网录入、断网刷新、同步、手机无横向溢出）
```

## 默认模式：八点仓壁距离差

**八个观测点**（四个角仓外侧）：12-上、12-左（左上）、10-上、10-右（右上）、18-下、18-左（左下）、16-下、16-右（右下）。11、15、14、13、17 号仓无直接观测点。

**使用步骤**
1. **填写底部基准**（每点一次）：`八点录入` → `八点底部基准`（或 `更多` → `八点底部基准`）→ 点击点号。填写基准标高、底部仓壁至基准线距离、基准线说明，勾选“基准关系已确认”和“方向规则适用”，保存后可做复核签认。录入页的基准卡片里也有“填写底部基准”按钮。
2. **确认设计仓壁位置**：`更多` → `项目设置` → “设计仓壁位置”。确认某标高范围内仓壁竖直后，该范围的设计修正值默认取 0；范围外须逐条录入设计修正值。
3. **录入**：`八点录入` → 新建轮次 → 点击点号 → 填写本次标高和本次距离 → 核对“基准值 → 本次值 → 差值 → 修正值 → 方向” → 保存。
4. **查看**：`九仓总览`（平面图、八点动态点、计算链）；点号详情（原始距离—标高、修正后位移—标高）；`角仓位移`（两个分量与组合位移示意）。

**计算**
- 差值 = 本次距离 − 该点底部基准距离
- 修正后 = 差值 − 设计距离变化（未提供时不输出方向）
- 图纸坐标（u 向右为正、v 向上为正）：左侧点 u = +修正后；右侧点 u = −修正后；上侧点 v = −修正后；下侧点 v = +修正后
- 角仓两点在同一目标标高都有有效分量时：组合位移量 = SQRT(u×u + v×v)，称“角仓两测点组合位移示意”，不是仓中心偏移
- 指标：H = 观测标高 − 起算标高；允许偏移 = MIN(H × 比例, 封顶值)。只在指标“已批准”、适用对象一致、输入完整时显示对照

**状态**：待录入 / 已录入 / 数据不完整（缺基准、缺距离、缺设计修正）/ 方向待确认（基准或方向规则未确认）/ 待复核（存疑、无效、读数突变）。

**可选模式**：`垂准仪`（滑模平台中心偏移 = −(光斑读数 + 投影板固定偏置)）和仓壁截面数据，与八点模式分开保存、分开计算。

## 九仓布局与方向

- 仓号位置按项目平面图固定：**上排 12 11 10，中排 15 14 13，下排 18 17 16**。旧版数据（按 16 17 18 排列定义的点号）打开时会按图纸位置自动迁移到新点号。程序不会自动重新排序。每个详情页都显示如“14 号仓｜中排中列”的位置说明。
- **图纸的上下左右不等于北南西东。** 在“设置 → 方向与坐标”中勾选“已确认”之前，所有图表都只标“图纸右/左/上/下”，不显示东西南北，也不显示北向箭头。
- 可以配置项目 +Y 轴相对图纸上方的角度、真北角、各仓设计中心坐标和中心距。缺少这些资料时，总览图醒目标注“示意布置，非按比例绘制”。
- 总览提供“简洁观测图”和“图纸参考图”两种显示方式，两者仓号位置一致。可在设置中上传筒仓布置图作为浅色底图，并调整透明度和对位。
- 导入的数据会校验仓号是否属于 10～18；不属于的行不导入，并给出提示。

## 垂准仪观测（平台偏移）

三个点要区分清楚：设计中心 D（即光斑投影点）、投影板刻度原点 O、平台中心标记 M。

- q：光斑相对刻度原点 O 的读数（X、Y 分别有正负）
- b：刻度原点 O 相对平台中心标记 M 的固定偏置
- **平台中心相对设计中心的偏移 = −(q + b)**，X、Y 分别计算；合成偏移量 = √(X² + Y²)

规则：
- 固定偏置未确认的，记录标为“基准待确认”，不输出平台偏移。
- 某个方向没读的，只显示已有方向的结果，不计算合成偏移量。
- 每条记录都保存原始读数，以及保存时带入的偏置快照。修改记录时保留修改历史。
- “平台偏移”和“成型仓壁偏移”（仓壁数据页，方式 A/B）分开保存、分开计算。在单仓详情中两者用不同颜色和线型叠加比较。

## 本轮观测（单人快速录入）

1. 在“本轮观测”页新建一轮，按需要调整观测顺序（程序不预设现场路线）。
2. 点击仓号卡片进入一屏录入页。页面会带入仓号、投影板和已确认的固定偏置，不沿用上次的读数。每个方向先填读数大小，再点方向按钮。
3. 保存前，页面会用文字复述计算结果，例如“14 号仓平台中心向东 8 mm、向南 5 mm”。保存后回到本轮页面，并高亮下一座待录入的仓。
4. 卡片状态分为：待录入 / 已录入 / 数据不完整 / 待复核。读数突变、偏置未确认、读数存疑时标为待复核；这只是提示，不修改原始数据。
5. 录入过程会自动保存草稿，断网或刷新后可以继续录入。“导出本轮记录”会导出九仓状态、标高、时间、原始读数、固定偏置、换算结果和备注。

> 单人快速录入只优化软件操作，不代表现场高处测量可以由一人独自完成。

## 离线与同步

- 应用可以安装为 PWA。断网时可以打开、录入和刷新，数据保存在本机浏览器里。
- 同步是可选的。在“数据”页填写同步地址（使用参考服务器时填 `/api`）后，恢复网络会自动上传，页头显示待同步数量和同步结果。
- 如果同一条记录在两台设备上都被修改，会列为冲突，逐个字段对比本机版本和服务器版本，由人工选择保留哪一个，不会静默覆盖。
- 参考服务器 `server/sync-server.mjs` 没有身份认证，只用于演示和内网测试；正式使用前请加上认证和 HTTPS。
- 未配置同步时，数据只保存在当前浏览器里，请定期在“数据”页导出 JSON 备份。

|---|---|
| `src/model/` | 数据类型、默认参数与演示数据、本地存储、同步 |

| `src/calc/overview.ts` | 九仓总览取数（同一标高 / 各仓最近一次） |

| `src/pages/` | 各页面：总览、本轮、录入、单仓详情、测点、仓壁数据、数据 |

| `e2e/offline.mjs` | PWA 离线录入、离线刷新、恢复同步、冲突的端到端测试 |

## 部署（Supabase 存数据 + Netlify 托管网站）

### 1. Supabase
1. 在 supabase.com 新建项目。
2. 打开 `supabase/001_silo_sync.sql`，把最后一段的“请改成你的口令”换成自己的同步口令，然后粘贴到 Supabase → SQL Editor 执行。
3. 在 Project Settings → API 中复制 **Project URL** 和 **anon public** key。不要使用 service_role key。

网页不能直接读写数据表，只能通过 `silo_sync_pull` / `silo_sync_push` 两个函数访问，而且必须提供同步口令。以后要改口令，重新执行 SQL 最后那一句即可。

### 2. Netlify
- **拖拽发布**：运行 `npm run build`，把 `dist` 文件夹（或打包好的 zip）拖到 app.netlify.com/drop。
- **连接 Git 仓库**：`netlify.toml` 已配置好构建命令 `npm run build` 和发布目录 `dist`。

### 3. 每台设备首次使用
打开网站 → “数据”页 → 同步方式选 Supabase → 填写 Project URL、anon key 和同步口令 → 保存 → 立即同步。
